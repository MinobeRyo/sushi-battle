# 寿司デッキバトル

回転寿司レーンでデッキを構築し、相手のお腹を満タンにさせて勝つカードゲーム風Webアプリ。

**最新版の企画書・カード一覧・運用ガイドは [資料一覧](docs/README.md) から確認できます。** Word文書と編集元Markdownを用意し、過去資料は日付入りのバックアップとして分けています。

CPU対戦・同じ端末での2人対戦に加え、**部屋コードで参加するオンライン2人対戦**に対応しています。オンラインも回転レーンと特急でデッキを組み、両者の手札と山札が尽きたら追加注文できます。購入と試合進行はサーバーで確定し、Socket.IO・HTTP/PHPの両方式で同期します。

タイトルの「カード図鑑」から通常55種類のカードを確認できます。名前・効果の検索やタイプ・系統の絞り込みに対応しています。

スマホの縦画面では、購入画面を大きな寿司が並ぶ縦2レーンで表示します。名前と価格を常時表示し、特急は注文中だけ下部のトレイに現れます。バトル画面も両者の状態を常時表示し、カードのイラストと文字の大きさを確保しています。画面に収まらない机や手札はスクロールして確認できます。下部の「手札へ／盤面へ戻る」で往復でき、縦画面・横画面のどちらでも操作できます。

## ゲーム概要

**2フェーズ構成**

1. **ドラフトフェーズ** — 回転レーンから流れてくる皿を軍資金（初期¥3,000）で購入し、最大20枚のデッキを組む
2. **バトルフェーズ** — 構築したデッキで相手のお腹ゲージを0→100にしたら勝ち

### CPU対戦 — 最弱・普通・挑戦

- **最弱**：従来の汎用カード中心のCPUを維持します。初期デッキは現在14枚（最大15枚）、追加注文は1,500円以内のランダム購入です。
- **普通**：赤身・巻物／軍艦・光り物・海鮮・肉寿司の5軸から、毎試合20%ずつの確率で相手を選びます。各デッキは寿司の定価合計3,000円・20枚以内の固定構成です。
- **挑戦**：肉寿司8枚＋巻物／軍艦12枚、寿司の定価合計4,500円の固定CPUデッキと対戦します。プレイヤーの初期予算は3,000円です。判断ごとに80%で盤面評価、20%で従来の簡易判断を使います。ガリは致死回避・消化量・残数、召喚はコンボ・AP効率・生贄の損得を考慮します。プレイヤーの手札と山札、自分の山札の中身は参照しません。80%は盤面評価を選ぶ確率で、勝率や厳密な最適解の保証ではありません。
- 普通・挑戦は山札の順番をシャッフルし、追加注文も同じ軸の固定1,500円デッキで補充します。相手のビルド名は対戦画面と開始ログに表示します。
- 「もう一回」でも選んだ難易度を維持します。普通の相手は再抽選し、同じ相手が続く場合もあります。
- デッキ構成は `src/data/cpuDecks.ts` の `entries`（初期）と `reorderEntries`（追加注文）で調整します。金額は寿司だけの合計で、CPUの召喚・防御・サイドメニューの処理は人間と同じルールを使います。

### 防御カードとガリ

先攻（P1）はガリ1個、後攻（P2）は2個を持って対戦を開始します。通常攻撃を受ける直前に、防御カードとガリを同じ画面で選び、ダメージと防御後のお腹を確認して確定します。サバ・イワシ生姜は召喚時に切れ味を払って防御を予約し、通常攻撃後に待機します。チーズは防御枠が空いていれば無料で待機します。

- 1回の通常攻撃に1個使えて、ダメージを50％軽減します。受けるダメージの端数は切り上げます（例：15→8）。APは消費しません。
- 防御カードは通常攻撃と海の幸三昧の再攻撃で使用できます。サバはランダム1枚、イワシ生姜は選択した1枚の攻撃を半減し、チーズはランダム1枚の攻撃から25％分（切り捨て）を引きます。固定ダメージは対象外です。
- 防御の回答まではダメージ・勝敗・手番交代を確定しません。
- 海の幸三昧を含む召喚時のダメージにはガリを使えません。防御待機カードがあれば再攻撃部分だけを防御でき、肉祭り・召喚連鎖・切れ味の固定ダメージはそのまま受けます。
- 使用可能なガリも防御カードもない場合、または攻撃が0の場合は選択を挟まず進みます。防御カードは使用後または次の相手ターン終了時に退場します。ガリは追加注文では補充されず、再戦時に先攻1個・後攻2個へ戻ります。
- 最弱・普通CPUは16以上の通常攻撃、または半減で敗北を回避できる攻撃にガリを使い、小さい攻撃では温存します。同端末の2人対戦では、防御するプレイヤーへ端末を渡します。
- オンラインではサーバーが防御者と残数を検証し、再送で二重消費しないようにします。防御待ちの切断から復帰しても選択を続けられます。

### サイドメニュー

7品から1品を購入します。永続型（ポテト・天ぷら・あおさ・インバウン丼）は購入した時点から自動で設置され、使い切りとラーメンは自分の手番に0APで使用します。未購入なら後半の追加注文でも購入できます。使い切りの品は使用後にもう一度購入でき、試合中の購入は合計2回までです。未使用の品との交換や、設置済みの永続効果の再購入はできません。寿司20枚・机8枠とは別枠です。注文回数は特急・大将のおすすめ・サイドで共通3回とし、サイド1品や大将の3皿セットも1回分を使います。唐揚げ・ポテト・天ぷら盛り合わせ・ラーメン・あおさの味噌汁・茶碗蒸しは300円です。

**インバウン丼**は肉丼ウニのせの500円サイドメニューです。購入時から試合終了まで、自分の生ハムの通常攻撃を＋2（1→3）、カルビ・和牛が生贄にする生ハム1体につき攻撃を追加で＋2します。相手には効果がありません。

## ドラフトフェーズ — レーン構成

| レーン | 仕組み |
|--------|--------|
| 汎用・サイドメニュー | ベルトで循環。たまご・サーモン系の汎用カード |
| ビルド系雑多 | ベルトで循環。各アーキタイプ・特殊効果・高級カード混在 |
| 新幹線ゾーン | 大将・サイドと共通3回まで。好きなカードを定価×1.5で即注文 → 皿が右から飛んでくる |

- 購入した皿の位置は穴（ダッシュ円）になりベルトは止まらない
- 皿をタップすると購入モーダルが開き、10秒で自動で閉じる。周回して別の皿に替わった場合、古い選択からは購入しない
- 皿の出現IDで同じ皿の二重購入を防ぎ、残高・20枚上限・共通の注文枠3回・締切を購入時に検証する
- 特急は支払い時点で購入確定。配送中に終了してもカードを保持し、受領で二重追加しない
- 初回の購入0枚は汎用カード10枚の代替デッキで開始する。追加注文の0枚は補充なしで再開する
- 90秒／45秒の残り時間は実時刻の締切から計算し、手動終了と時間切れの完了処理は一度だけ行う

### 大将のおすすめ（試作）

タブレットの「大将のおすすめ」は **750円分が500円に！（たまにハズレ）**。各購入フェーズ1回、通常価格の合計750円に相当する寿司3枚を受け取ります。寿司の20枚上限に含み、特急・サイドと共通の注文枠3回のうち1回を使います。

試作確率は通常77％・ハズレ20％・レア3％です。ハズレでは3枚のうち1枚が「真横を向いた軍艦」または「ネタが落ちた寿司」となり、基本攻撃が半分（切り捨て）になります。レアでは1枚が「真横を向いたマヨコーン」（2AP・攻撃12・光る縁）に替わります。確率は `src/features/draft/draftEngine.ts` の定数で調整します。

### 改善案の試作（2026-10-07）

- えび軍艦：召喚時、山札から軍艦以外の巻物をランダムに1枚、手札へ。
- いくら軍艦：召喚時、1〜2APの軍艦以外の巻物をランダムに1枚、山札へ生成。
- とびこ軍艦：召喚時の複製確率を自分の累計召喚順に75％→50％→25％→0％へ。複製されたカードも通算します。
- 合鴨寿司：3AP・攻撃2・4ターン持続。場にいる間、自分の生ハムの攻撃＋2。合鴨同士は重複しません。
- ボタンエビ：場にいる間、海の幸三昧が発動するたびに自身1枚につきえび1枚を山札へ生成。
- たまご：召喚時に自分のお腹−5。シーフード軍艦に海鮮タグ、たこわさに巻物・軍艦タグを追加。
- チーズ：通常攻撃後に無料の防御待機。次の相手の攻撃時、ランダム1枚を25％軽減。
- 遊び方の冒頭を購入から勝利までの4手順の図解に変更し、コンボ説明を短縮。本文を大きくし、スマホでは紙面を一枚幅で縦に表示。肉寿司専用ページは削除しました。ツナを淡いピンクのほぐし身に、合鴨を白い脂の縁がある薄切りに変更。いくら・とびこは単色の土台を削除し、丸い粒だけで盛り付けています。巻物は端の断面だけ白くし、側面を海苔で閉じ、納豆巻きの糸を削除しています。

起動後、URL末尾に `#improvements-demo` を付けると変更点を確認できます（例：`http://localhost:5173/#improvements-demo`）。新モデル、防御画面、山札の確認、遊び方を試せます。デモは実際の対戦状態を変更しません。

- 赤身三種盛り成立後は、机の鉄火巻き1枚につき自分の開始時に通常回復後のAP・当ターン上限+1（通常上限10を超える）。ビントロは成立後の召喚時に2枚ドロー（手札7枚まで）＋自分のお腹−3（下限0）です。
- いかにぎりは2AP・攻撃7・200円の即時型を維持。召喚の2AP支払い後、自分の机にたこ系がいれば現在APを1回復します（当ターン上限まで）。たこわさ・兼用ネタ・ペア消費済みも数え、複数でも回復1。相手の机・手札・山札は対象外で、AP1からは召喚できません。持続型のいかは変更せず、既存の海鮮連鎖・海の幸三昧も維持します。
- カニ軍艦は5AP・400円を維持し、攻撃16へ変更。召喚時点で机にいる軍艦以外の巻物すべてに当ターン攻撃+2を加えます（兼用・即時型も対象、後から出した巻物は対象外）。複数回と他の一時強化に加算でき、通常攻撃の防御解決後に解除します。カニ自身の巻物コンプの枚数算入と軍艦1.5倍は維持します。
- マグロは召喚時に山札の赤身1枚をランダムに引きます（手札7枚まで、対象なし不発、消費AP軽減を保持）。三種盛りは不要で、共有ログに対象名は公開しません。づけマグロは相手本人の開始時の消化を通常1回、自分の三種盛り成立後は2回停止。再付与は残回数と付与回数の最大値で、加算・短縮せず、茶碗蒸しで解除できます。
- ツナ軍艦は2AP・150円・攻撃6を維持し、召喚時に自分の手札・山札の赤身タグ付きで消費AP1以上の個体から均等に1枚抽選して消費AP−1。対戦中その1枚だけに残り、累積して0まで下がります。三種盛りの成立は不要、対象なしなら不発です。カードを移動せず、共有ログには対象名・IDを公開しません。
- 通常のサーモンは2AP・攻撃8・200円を維持し、召喚時に相手の机の持続カード1枚を選んで破壊します（生ハムも対象）。対象なしなら通常召喚でき、即時型・自分のカード・手札・山札は対象外です。破壊にガリは使えず、既に得た永続バフや現在APは巻き戻しません。サーモン自身の通常攻撃は従来通りです。
- 焼肉寿司は攻撃4・3AP・300円・3ターン持続と、相手のお腹50以上で攻撃+2を維持。自分の終了時、通常攻撃後に対戦が続く場合、1個体につき生ハム1枚を山札のランダムな位置へ追加します。寿命減算前に生成してから終了時ドローするため、召喚ターンと最後のターンも含め最大3枚です。
- 肉祭りは同ターンの生ハム生贄累計2体・1ターン1回・即時5ダメージに加え、山札に0AP生ハム1枚を追加し、全生ハムの攻撃+1を付与します。攻撃強化は試合中累積し、机・手札・今後生成する生ハムにも適用します。生ハムは基本攻撃1・3ターン持続です。
- えびは3AP・200円・攻撃5・2ターン持続。召喚時に山札の持続いか・たこからランダム1枚を引きます。海の幸三昧では海鮮の合計攻撃を50%にして切り捨てた後、通常のえび1枚につき固定+7を加算します。えびはペア条件に数えず、通常攻撃・召喚連鎖には+7しません。

**カードタイプ 2種**

- **即時型** — 出したターンに攻撃して捨て札へ
- **持続型** — 机に残り毎ターン継続ダメージ（満腹度=持続ターン数）

## バトルフェーズ

- **勝敗**: お腹ゲージが100に到達した側の負け
- **AP（食欲ポイント）**: 初期2、通常上限10。CPU戦は毎ターン+1、二人対戦は2ターンで+1。赤身三種盛り後の鉄火巻きは、自分の開始時に通常回復後AP・当ターン上限へ1枚につき+1を別途加算
- **消化**: 本人の手番開始時にお腹が減る。`min(5, 1+ラウンド)`。消化停止もその開始時に消費する
- **机**: 最大8枚。持続型は `max(満腹度, 2)` ターン残って毎ターン攻撃する
- **手札**: 上限7枚。引けない分は山札に残る
- **追加注文タイム**: 両者の手札と山札が尽きたら発生。¥1,500 / 45秒で補充する
- **コンボ**: 6役。発動の仕方は「永続効果（1試合1回）」「都度発動」「状態継続」の3種類

詳しくは [最新版のカードとコンボ一覧](docs/latest/すしバトル_カードとコンボ一覧_2026-10-07.md) を参照。

## 起動方法

初回のみ依存をインストールします。

```bash
npm install
```

オンライン試遊ではターミナルを2つ開きます。

```bash
# ターミナル1：対戦サーバー（http://127.0.0.1:3001）
npm run server
```

```bash
# ターミナル2：ゲーム画面（http://localhost:5173）
npm run dev
```

2つのブラウザ画面で「オンライン対戦」を選び、片方で部屋を作成、もう片方で6桁のコードを入力します。CPU戦と同端末2人対戦は `npm run dev` だけでも動作します。サーバーコードを変更しながら試す場合は `npm run server:dev` で自動再起動できますが、そのたびに進行中の部屋は消えます。

ブラウザはページと同じ接続先の `/socket.io` にアクセスし、Viteが `http://127.0.0.1:3001` へHTTP/WebSocketを中継します。`vite.config.ts` は5173番の使用中に別ポートへ自動変更しない設定です。サーバーポートを変更する場合はプロキシ先も合わせて変更します。

### サーバー設定

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `HOST` | `127.0.0.1` | 対戦サーバーの待受アドレス |
| `PORT` | `3001` | 対戦サーバーの待受ポート |
| `SUSHI_ALLOWED_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 接続を許可する画面のオリジン。複数はカンマ区切り |

公開URLが決まったら `SUSHI_ALLOWED_ORIGINS` をそのURLのオリジンへ合わせ、同じ公開URLの `/socket.io` を対戦サーバーへ中継します。Viteの開発用プロキシは本番用静的ファイルには含まれません。`/health` は対戦サーバーの動作確認用です。

### 通信試遊版の範囲と制約

- 2人が揃うと初回購入（¥3,000 / 90秒）を同時開始します。レーンは各自独立で、サーバーが皿を供給します。残金・20枚上限・共通の注文枠3回・皿の周回・締切をサーバーで検証し、相手の購入内容は公開しません。
- 両者の購入完了または締切で対戦を開始します。両者の手札・山札が尽きると追加注文（¥1,500 / 45秒）に移り、両者が完了すると同じ試合を再開します。再戦時は初回購入からやり直します。
- PCで皿にカーソルを合わせるとハイライトと名前・価格を表示し、ローカル・オンラインともレーンは流れ続けます。オンラインの購入締切も進みます。購入済みカード・残金・特急配送・締切は復帰後も保持します。
- コンボ演出は本人・相手の両画面に表示します。双方の「状態・コンボ」から切れ味、AP、強化・追加ドロー・消化停止などの効果、コンボ進捗を確認できます。相手の手札の内容と山札順は公開しません。
- サーバーが手番・手札・AP・机上限を検証し、確定した状態を本人向けに送ります。相手の手札の中身・両者の山札順・再参加トークンを状態配信へ含めません。
- 操作は対戦ID・更新番号・操作IDで照合します。同じ操作IDの再送は重複処理せず、旧対戦の操作や別内容でのID再利用を拒否します。
- 片方が切断すると対戦操作を停止します。120秒以内なら、同じタブの再参加トークンで元の席に復帰できます。猶予切れは部屋終了で、棄権勝利の付与はまだ行いません。
- 接続中の席へ正しいトークンで復帰した場合は旧接続を置き換えます。明示的な退出は部屋を閉じ、再戦は勝敗確定後に両者が希望すると始まります。
- 部屋と試合はサーバー1プロセスのメモリで保持します。サーバー再起動後の試合復元、DB保存、複数サーバーへの分散は未対応です。
- ローカル121件・オンライン48件・PHP中継16件の自動テストを確認しています。今回の購入対応は同一端末の2タブで確認しており、別端末2台と公開サーバーでの確認は未実施です。

### オンライン購入の実画面確認（2026-09-28）

HTTP通信のブラウザ2タブで、通常皿の購入、特急の支払い、未受領の特急を保持したリロード復帰、先に完了した側の待機、購入カードでの対戦開始を確認しました。両者がカードを使い切ると¥1,500 / 45秒の追加注文に移り、P1は0枚、P2は特急で1枚購入して再開できました。再開後の手番・お腹・補充カードも保持され、両タブのコンソールエラーはありませんでした。

### 実ブラウザでの確認（2026-09-25）

実ブラウザ2タブで固定16枚の対戦をターン64・P2勝利まで進め、双方の勝者とお腹が一致することを確認しました。固定デッキの自動補充、巻物コンプのドロー+1、召喚ボタンのダブルクリックで1枚だけ召喚されることも確認しています。

P2の再読込で手札・手番を復元し、相手の一時離脱中はP1の操作が無効になり、復帰後に再開しました。双方の再戦合意でターン1・お腹0・手札5枚／山札11枚へ初期化され、退出で部屋が終了することも確認済みです。同じ端末の2タブでの確認であり、別端末2台やゼミのネットワークでの確認ではありません。
