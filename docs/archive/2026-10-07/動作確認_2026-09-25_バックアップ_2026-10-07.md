# 2026-09-25 共通エンジン・通信試遊の確認

## 実装した範囲

- 店員の解説を実装済みの6役へ同期。巻物は机に同時3枚／5枚、光り物は大葉の累計3枚・切れ味+3と明記。
- 対戦を `src/game/`、購入と締切を `draftEngine.ts` へ分離。固定のP1/P2、カード個体ID、入力に対する状態遷移を使用。
- CPU・同端末2人・通信対戦で共通の対戦処理を使用。CPUの召喚時ドローや追加ダメージも、人と同じく1枚ごとに解決する。
- Node.js + Socket.IOによる数字6桁の部屋、固定16枚デッキ、サーバーでの操作検証と本人向け状態配信。
- 切断中の停止、120秒の復帰猶予、再読込復帰、双方合意の再戦、退出。両者のカードが尽きると固定デッキを自動補充。
- 基本CSSの余白リセットをbaseレイヤーへ移し、ロビーなどのTailwindの余白指定が反映されるように修正。

## 実ブラウザで確認

ローカルのVite（127.0.0.1:5173）と対戦サーバー（3001）を使用。ブラウザの画面操作で確認し、画面への状態注入は行っていない。

| 操作 | 結果 |

| 2タブで作成・6桁コード参加 | 異なるP1/P2の手札が表示され、P1から開始 |
| チーズの召喚をダブルクリック | 机1枚、手札1枚消費、AP1消費だけ。相手画面も一致 |
| 召喚・ターン交代・カードを使い切る | 両画面が同期。固定デッキの補充と巻物ドロー+1も確認 |
| 1試合の完走 | T64で双方にP2の勝利。P1のお腹100、P2は89で一致 |
| 再戦希望 | 片方だけでは結果を保持。両者の合意でT1、お腹0、手札5、山札11へ初期化 |
| P2の再読込 | 部屋・手札・手番を保持して復帰 |
| P2が別画面へ移動 | P1に待機表示、ターン終了無効。P2が復帰すると操作再開 |
| 部屋の退出 | 相手もロビーへ戻り、新しい部屋を作成可能 |
| 店員の解説 | 上部から下部までスクロールし、条件・頻度・効果を確認 |
| 初回0枚、ドラフト時間切れ | 代替10枚デッキで対戦開始。Reactの状態更新エラーなし |

| 特急の大トロ注文直後、受領せず終了 | 750円を支払い、対戦開始時に大トロ1枚を保持 |
