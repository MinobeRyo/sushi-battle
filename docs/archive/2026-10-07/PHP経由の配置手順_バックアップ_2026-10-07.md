# ゼミサーバーでオンライン対戦を動かす

公開画面 → `api.php` → 同じサーバー内の対戦プログラム、の順で通信します。PHPは短い要求だけを中継し、対戦のルールと部屋の管理はNode.jsが担当します。2026-09-25、公開した診断ページでPHPの実行、curl拡張、`127.0.0.1:3001/health`への接続がすべて成功したことを確認しました。この診断だけで実際の対戦まで確認できたわけではありません。

## 配布物を作る

Macのプロジェクト内で実行します。画面のビルドにはNode.js 24を使います。ゼミ側の対戦サーバーは確認済みのNode.js 20.20.2で動かせます。

```bash
node scripts/package-gms.mjs
```

`release/gms`に次の2つのフォルダができます。画面はPHP通信を使う設定でビルドされ、`api.php`も同梱されます。

| Macの配布物 | Cyberduckで置く場所 |
| --- | --- |
| `release/gms/sushi-battle` の中身 | `/home/h0/ryom13/public_html/sushi-battle/` |
| `release/gms/sushi-battle-server` の中身 | `/home/h0/ryom13/sushi-battle-server/` |

フォルダを二重にしないでください。公開先の直下に`index.html`、`api.php`、`assets`が並び、対戦サーバー側には`package.json`、`package-lock.json`、`server`、`src`が並ぶ状態です。

## 今の手動起動から更新する

1. 対戦中の人がいない状態にします。更新で対戦サーバーを再起動すると部屋は失われます。
2. ゼミにログインし、対戦サーバーを起動したターミナルで **Ctrl+C** を押します。
3. 上の2つの配布物を、それぞれの場所へ上書きアップロードします。診断用の`check-route.php`だけでは通信機能は追加されません。
4. ゼミ側のターミナルで次を実行します。

```bash
cd /home/h0/ryom13/sushi-battle-server
npm ci --omit=dev
HOST=127.0.0.1 PORT=3001 SUSHI_ALLOWED_ORIGINS=https://gms.gdl.jp npm run server
```

5. [通信確認](https://gms.gdl.jp/~ryom13/sushi-battle/api.php)を開き、`{"ok":true,"transport":"php-polling"}`が表示されることを確認します。PHPは新しい通信方式に対応したサーバーかも確認するため、古いプログラムのままなら503になります。
6. [ゲーム](https://gms.gdl.jp/~ryom13/sushi-battle/)を再読み込みし、オンライン対戦で部屋を作ります。もう1つのブラウザまたは別の端末からコードを入力し、召喚とターン終了が両方に反映されるか確認します。

手動の`npm run server`はターミナルを閉じると止まることがあります。ログアウト後も動かす運用と転送の自動化には、[GitHub Actions自動デプロイ](GitHub%20Actions自動デプロイ.md)の初回設定を使います。

## 通信と運用の範囲

- 対戦中は画面ごとにおおむね1秒おきに状態を取得します。相手側の表示には通常1秒程度と通信時間の遅れがあります。操作した本人には要求の応答で状態を返します。
- 待機中や非表示の画面は間隔を長くし、失敗時は間隔を広げて再接続します。前の要求が終わるまで次を送信しません。
- 相手の手札・山札順・参加用トークンは公開状態に含めません。誰の操作か、手番、AP、同じ操作の再送をサーバーで検証します。
- ブラウザの休止や通信断は即時には検知できません。一定時間通信がない席は切断扱いになり、復帰猶予を過ぎると部屋を閉じます。
- Node.jsは引き続き`127.0.0.1:3001`で起動が必要です。PHPファイルだけでは対戦を実行できません。
- 多人数での負荷はまだ実測していません。まず2人で試遊し、利用人数を増やすときに応答時間とサーバー負荷を確認します。

`api.php`の転送先は固定で、任意のURLやコマンドは受け付けません。POSTは公開元`https://gms.gdl.jp`を確認し、本文16 KiBまで・待機3秒までに制限します。共有ホストの同一オリジン内にある他のアプリを分離する仕組みではないため、参加用トークンはURLに載せません。

開発中の標準接続は従来のSocket.IOのままです。PHP方式の画面をローカルで試す場合は`VITE_ROOM_TRANSPORT=php npm run dev`を使います。Viteの開発用中継でHTTP通信を確認できますが、PHP実行の検証は別です。
