A1

肉祭りコンボのバフが実装されていない

高S · 30分
現状
BattleScreen.tsx の COMBOS で、肉祭りの applyBuff は (buff, draw) => ({ buff, draw }) ＝ 何もしない関数です。実際に効くのは instantDmg: 12 だけ。
問題
画面には「同ターン肉寿司攻撃ボーナス×2」と表示されるのに何も起きません。企画書の意図は「そのターンの肉寿司カードの終盤強化ボーナスを×2」です。
修正案
2案あります。
  • 案1（実装重め・企画書どおり） — calcFieldDmg に「肉祭り発動中フラグ」を渡し、belly_boost_* の effectBonus を2倍にする。ただし現在のコンボは1試合1回きりなので、「そのターンだけ」を表現するには発動ターンを記録する仕組みが要ります。
  • 案2（軽い・推奨） — 説明文を実装に合わせて「即時+12ダメージ」に直す。肉寿司ビルドはすでに belly_boost で終盤に伸びるので、コンボは素直な打点として残す。
影響
案2なら文字列1箇所。案1は calcFieldDmg のシグネチャ変更＝呼び出し4箇所に波及します。
A2

太巻きの multi_base が完全に無効

対応済2026-08-22 実装
だった状態
applySummon の効果 switch に multi_base の分岐がなく、召喚履歴には card.base（＝「太巻き」）しか積まれていませんでした。4AP・¥300のカードが、攻撃5・持続3Tの平凡なカードになっていました。
決めたこと
太巻きが名乗る base を マグロ・えび の2つに決定。巻物アーキタイプは今までどおり1枚ぶんのまま（複数枚カウントはしない）。
  • マグロ — 赤身三種盛り発動後、攻撃が5→7になります。持続3Tなので総ダメージ15→21。成立判定はカードID（maguro/chutoro/otoro）なので太巻きでは赤身三種盛りを成立させられず、恩恵だけ受ける形です。「赤身を揃えてから太巻きを置く」順序が生まれます。
  • えび — 海鮮連鎖の起爆役になります（机の連鎖カード1枚につき+3）。いか・たこを先に並べておく必要があるので、海鮮ビルドの動きは壊れません。
  • いか・たこは入れない — 入れると太巻き1枚で海の幸三昧（机の総攻撃力×2）が成立してしまうため。
実装
Card 型に subBases?: string[] を追加し、太巻きに ['マグロ','えび'] を設定。変更は4箇所です。
  • applySummon — 同時型コンボ用の thisTurnBases に base + subBases を積む
  • applySummon — 海鮮連鎖の CHAIN_TRIGGER_BASES 判定が subBases も見る
  • calcFieldDmg — base バフの参照を subBases まで広げる（過去の実装方針メモに抜けていた箇所。ここを直さないとマグロのバフが乗りません）
  • 効果テキストを実際の挙動に合わせて更新。未使用だった multi_base_combo キーも削除
複数の base バフを持つ場合は合計せず最大値を1つだけ受けます（現状マグロのバフしか存在しないので実害はありませんが、将来バフが増えたときに青天井にならないように）。
企画書での扱い
企画書の記述は表の1セル「複数base内包、コンボ条件を複数満たせる」だけで、どの base を内包するかは未定義でした。implementation_flow.md の Phase 1-3 に相当します。
A3

二人対戦だけ持続カードが2回攻撃・2回消耗・2回ドローする

対応済2026-08-22 修正
だった状態
二人対戦では、ターン終了処理が2箇所で二重に走っていました。自分のターン終了時（endTurnTwoPlayer）と、相手のパス画面（handlePassReady）の両方で、同じプレイヤーについて次の3つが実行されていました。
  • 持続フィールドの攻撃
  • turnsLeft の減算
  • ドロー（1 + drawBonus 枚）
結果として、各プレイヤーが1ラウンドあたり2回攻撃し、2回場が消耗し、2枚多く引いていました。CPU戦はいずれも1回だけです。
影響していたこと
消化（お腹の回復）は1ラウンドに1回のままなので、二人対戦では持続型デッキが相対的に約2倍強くなっていました。満腹度3の巻物が実質1.5ラウンドで消えるため、カードに表示される「3T」も意味を成していませんでした。ドローが倍だったぶん、山札の消費も倍速です。
修正
handlePassReady から攻撃・turnsLeft 減算・ドローの3つを削除しました。パス画面は手番の受け渡しと、次にアクティブになる側の消化・AP回復だけを担当します。攻撃と場の消耗とドローは、各プレイヤー自身のターン終了時に1回だけ処理されるようになり、CPU戦と同じ進行になりました。
副次的な確認
ドローの二重実行は当初の指摘に含まれていませんでした。修正のために処理を追ったところ発見したものです。原因は同じ（パス画面がターン終了処理を重複して持っていた）なので、まとめて解消しています。
残る作業
二人対戦のバランスが実質的に変わったので、E4 のシミュレーションで決着ターン数を確認したいところです。

ドラフトのタイマーが state 更新関数の中で onComplete を呼ぶ

C未実装のコンボ

C1

光り物三昧 — 大葉カードが2種しかなく成立不能

中M · 半日
条件と効果
大葉トッピングのカードを累計3枚召喚 → 切れ味スタック +3（card_pool.md 版）。design.md 版は「切れ味 ×1.5倍」ですが、切れ味が加算スタックとして実装されている以上、+3 のほうを採るのが整合的です。
問題

  • 案3（推奨） — 条件を「薬味トッピング付きカードを3枚」に広げる。トッピングは大葉・ネギ・しそ・わさび・生姜・オニオン・アボカドの7種あるので、光り物以外のビルドにも意味が出ます。ただし「光り物」三昧という名前とは合わなくなります。
影響
COMBOS に1件追加＋topping_count 判定の実装。案1ならカード追加も。

D数値バランス

全54枚の「総ダメージ ÷ AP」で並べ直した結果です。総ダメージは持続型なら 攻撃力 × 残存ターン数、即時型なら攻撃力そのものです。

D1

持続型が即時型より約1.5倍効率が良く、上位8枚が全部巻物

高M · 半日
現状
平均の「総ダメージ ÷ AP」は持続型 4.92 / 即時型 3.26。上位8枚はすべて持続型の巻物系です。除去手段が存在しないため、持続カードは出したら必ず全ターン分殴りきります。
問題
フィニッシャーであるはずの大トロ（5AP・¥500）が4.40なのに対し、アボカド巻き（1AP・¥150）が8.00で倍近く上回ります。「巻物を並べるのが最適解」という単一の正解ができてしまい、赤身・肉寿司・光り物の存在意義が薄れます。
修正案
持続型のみ攻撃力を下げるのではなく、持続型はターン経過で攻撃力が落ちるルールを入れるのが効果的だと考えます（例：残存ターンが1減るごとに攻撃 −1）。「食べかけの寿司が乾いていく」という題材とも噛み合います。
数値だけで調整するなら、満腹度4の持続カード（アボカド巻き・納豆巻き・鉄火巻き）を3Tに下げるだけでも上位が入れ替わります。
影響
ルール変更なら calcFieldDmg。数値のみなら cards.ts。いずれもE4のシミュレーションで検証したいところです。

コハダが使うと損をする罠カードになっている

中S · 1時間

問題

AP成長式が2箇所に別々にハードコードされている

低S · 30分
現状
CPU戦は Math.min(INIT_AP + newTurn - 1, 10)（3箇所）、二人対戦は Math.min(INIT_AP + Math.floor((newTurn - 1) / 2), 10)（1箇所）と、別々の式が直接書かれています。
問題
ロジック自体は正しい（二人対戦は2手番＝1ラウンドなので2で割るのが正解）のですが、片方だけ直して片方を忘れる事故が起きやすい形です。同じ理由で digestionAmount の引数も turn と Math.ceil(turn / 2) に分かれています。
修正案
roundOf(turn, mode) という関数を1つ作り、AP成長も消化量もそこから導出します。「ターン」と「ラウンド」の違いがコード上で明示されるので、読みやすさも上がります。
