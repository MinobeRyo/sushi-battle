## 対戦サーバーの起動

Node.js/npmの利用、SSHまたはコマンド実行用の管理画面、利用可能な待受ポートは未確認です。
使える場合は、サーバー上のターミナルで実行します。

```bash
cd /home/h0/ryom13/sushi-battle-server
npm ci --include=dev
HOST=127.0.0.1 PORT=3001 SUSHI_ALLOWED_ORIGINS=https://gms.gdl.jp npm run server
```

現状はTypeScript実行用の `tsx` が開発依存にあるため、`--include=dev` を指定します。
`SUSHI_ALLOWED_ORIGINS` はドメインまでを指定し、`/~ryom13/sushi-battle/` は含めません。
3001番が別用途に使われている場合は、管理者と相談して別のポートを割り当て、中継設定も合わせます。

このコマンドは前面で起動する動作確認用です。常時運用の起動・停止・再起動方法はサーバー管理者と調整します。
起動すると部屋をメモリに保持し、サーバー再起動時には進行中の部屋が消えます。

## Webサーバー側の中継

現在のクライアントは、画面と同じドメインの **`/socket.io/`** へ通信します。
ページをサブフォルダへ置いても、通信先は `https://gms.gdl.jp/socket.io/` のままです。
`vite.config.ts` のプロキシはローカル開発専用で、本番の静的ファイルには入りません。

管理者に確認する内容:

> Node.jsの対戦サーバーをユーザー領域で常時起動できますか。
> 使用可能なポートを割り当て、HTTPSの `/socket.io/` から `127.0.0.1:3001/socket.io/` へ、HTTPとWebSocketの中継を設定できますか。
> 既存アプリとパスが競合する場合は、利用可能な専用パスを教えてください。

専用パスを使う場合は、ブラウザと対戦サーバーのSocket.IOの `path` を同じ値へ変更してからビルドし直します。
Cyberduckでファイルを送れることだけでは、Node.jsの起動やこの中継の利用可否は判断できません。
